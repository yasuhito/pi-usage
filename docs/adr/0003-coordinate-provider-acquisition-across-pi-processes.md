# Coordinate provider acquisition across Pi processes

Use a provider-independent acquisition-coordination boundary to prevent session startup, `/reload`, `/new`, and concurrent Pi processes from independently sending duplicate provider usage requests, initially applying it only to Claude. Processes share sanitized successful observations and scheduling metadata in a OS-managed user-runtime location, reuse successful observations for three minutes, and coordinate all temporary-failure backoff; a 429 honors `Retry-After` with a fifteen-minute floor. Concurrent followers wait within a bounded interval for the owner’s result, and an expired lease permits recovery after owner failure; they never bypass coordination after a wait timeout. A newer shared temporary failure makes the last successful Claude observation stale until its reported reset, while a credential rejection or terminal response suppresses duplicate attempts for fifteen minutes. Existing monitor refresh triggers read shared updates without adding a file watcher.

OAuth credentials and raw provider responses remain memory-only. Shared entries are partitioned by an HMAC of the OAuth credential using an ephemeral user-runtime secret rather than by a persisted plain credential fingerprint. The first implementation supports only an ownership-checked Linux `XDG_RUNTIME_DIR`; without it, including on other operating systems, Claude acquisition remains unavailable instead of falling back to independent requests or durable storage. This accepts ephemeral local sharing of usage percentages and reset times so every session can present recent usage without requiring a daemon or leaving healthy followers unavailable.

Place the provider-independent coordinator after authentication resolution and immediately before the provider HTTP exchange. Implement its versioned state protocol with Node filesystem primitives: atomic directory creation for leases, atomic rename for safe stale-lease reclamation, and temporary-file rename for state publication. The owner heartbeats its lease; ten seconds without renewal makes it reclaimable. Followers wait at most six seconds, re-read shared state, and then return a temporary failure to the ordinary backoff rather than bypassing coordination. Do not add a locking dependency.

Opportunistically remove entries untouched for twenty-four hours without failing acquisition when cleanup fails. Treat unsafe directory ownership or permissions as fatal to Claude acquisition, but quarantine malformed, out-of-range, or incompatible state entries and recover under the lock. Notify TUI users once per process when the secure runtime location is unavailable, retain the ordinary `Claude wk unavailable` footer, and document the Linux `XDG_RUNTIME_DIR` requirement. Verify the guarantee with deterministic unit tests and a real multi-process integration test, including expired-lease recovery and cancellation.
